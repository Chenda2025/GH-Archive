Hadoop MapReduce — how it works

Python Streaming job: parse every line manually with json.loads

MAP

Read & parse each JSON line

Mapper reads stdin line-by-line. Each line → json.loads() → Python dict. No schema — re-parse every record.

event = json.loads(line)
emit(f"evt|{repo}|{event_type}")
emit(f"user|{user}")
emit(f"push|{repo}")  # if PushEvent
hadoop/mapper.py
SHUFFLE

Sort all key/value pairs

All mapper output is written to disk, then sorted by key (evt|repo|type, user|login, lang|Java…).

mapper.py < input.json | sort | reducer.py
app/hadoop_engine.py
REDUCE

Sum counts per key

Reducer groups sorted keys and sums values → top repos, top users, languages, event types.

user|octocat    → 120
evt|apache/spark|PushEvent → 256
lang|Java       → 214
hadoop/reducer.py
WeaknessParse cost grows linearly — every new hourly dump re-parses all lines.
OutputTop repos, users, languages, event types + parse time metric.
⚡

Apache Spark — how it works

Native spark.read.json() + Catalyst Optimizer on nested schema

1

Infer nested schema once

Spark scans JSON and builds a struct schema: actor.login, repo.name, payload.commits, payload.pull_request.base.repo.language…

df = spark.read.json(path)
df.printSchema()
# root
#  |-- actor: struct (login, id, …)
#  |-- repo: struct (name, …)
#  |-- payload: struct (…)
app/spark_engine.py
2

Filter PushEvent with Catalyst

DataFrame filter pushes predicate down — only matching rows are processed further.

pushes = df.filter(F.col("type") == "PushEvent")
top = pushes.groupBy("repo.name").count()
         .orderBy(F.desc("count")).limit(15)
spark/github_profile.py
3

Rank projects, users & languages

GroupBy + orderBy on nested columns. Catalyst generates optimized physical plan with projection pruning.

top_users = df.groupBy("actor.login").count()
languages = df.select(coalesce(
  payload.pull_request.base.repo.language,
  payload.forkee.language, …))
app/spark_engine.py
StrengthSchema inferred once, reused for all queries. Catalyst + Tungsten = columnar, fast.
OutputSame rankings as Hadoop + schema tree + faster total time.

Side-by-side comparison

Step Hadoop Spark
Read JSON json.loads() per line in Python spark.read.json() — batch schema infer
Schema None — manual dict walk each time Nested struct built once (actor, repo, payload)
Filter PushEvent if event_type == "PushEvent" in mapper df.filter(type == 'PushEvent') — Catalyst pushdown
Aggregate Map emit keys → shuffle → reduce sum groupBy().count().orderBy() — whole-stage codegen
Speed Slower on nested JSON (parse overhead) Faster — schema reuse + Catalyst optimizer
